# 多批次目录/压缩包批量导入 设计规格

> **状态：已确认，待实现**（用户 2026-09-01 指示"开始实现"）。

**目标：** 支持将多个批次的数据文件一次性存入系统——上传 zip 包（第一层子目录=一个批次），系统按清单校验后批量创建批次并入库文件；提供导入模板（manifest.csv）下载。

**技术栈：** FastAPI + SQLAlchemy + SQLite（后端）、Vue 3 + Element Plus（前端）、MinIO（对象存储）

---

## 一、需求与现状

### 1.1 现状

- 单批次流程：新建批次（BatchCreateView 表单 10+ 字段）→ 批次详情 → 上传页（UploadPanel 分片直传 MinIO，10MB/片，断点续传，文件挂 batch_id）。
- 上传接口：`POST /api/v1/batches/{batch_id}/files/upload/init|complete`（挂 batch_id，presigned 直传）。
- 无任何批量建批次/批量导入能力；多批次入库需反复手工操作。

### 1.2 已确认决策（2026-09-01 用户选择）

| 决策点 | 结论 |
|--------|------|
| 批量形态 | **目录/压缩包导入**：第一层子目录=一个批次，目录内文件归入该批次 |
| 元数据要求 | **完整字段强制**：每批次全部字段必须提供，否则不入库 |
| 模板下载 | **必须提供**（manifest.csv 模板 + 字段说明） |
| 传输架构 | **zip 直传 MinIO + 后端异步导入任务**（方案 A，GB 级大包支持） |

---

## 二、导入包结构约定

```
数据导入包.zip
├── manifest.csv                    # 顶层批次清单（UTF-8 with BOM，Excel 可直接编辑）
├── F01_20250901/                   # 批次目录（目录名与清单"目录"列对应）
│   ├── 1.dat
│   └── 振动/2.bin                  # 支持子目录，object_key 保留相对路径
└── F02_20250901/                   # 批次 2 目录
    └── ...
```

### manifest.csv 列定义（完整字段强制）

| 列 | 必填 | 说明 |
|----|------|------|
| `目录` | ✅ | 批次目录名，须在 zip 中存在且非空 |
| `batch_no` | 条件 | 编号自动生成规则**未启用**时必填；启用后留空（自动生成） |
| `device_no` | ✅ | 设备/机组编号 |
| `device_model` | 选填 | 设备型号 |
| `station` | 选填 | 所属场站 |
| `license` | ✅ | 枚举（内部专用/公开/受限，与系统字典一致） |
| `sensitivity` | ✅ | 枚举（内部/机密等，与系统字典一致） |
| `owner_contact` | 选填 | 负责人及联系方式 |
| `is_synthetic` | ✅ | 0/1 |
| `operating_condition` | 选填 | 运行工况 |
| `weather` | 选填 | 天气条件 |
| `数据对应设备:状态类型` | ✅ | 枚举：风电/火电/光伏 |
| 任意附加列 | 选填 | 列名=扩展字段键名，值收集进该批次 extras |

## 三、模板下载

- `GET /api/v1/batch-imports/template` 返回 manifest.csv（UTF-8 with BOM）：表头行（上表全部固定列）+ 一行合法示例数据。
- 模板由后端按当前系统字典实时生成（license/sensitivity 枚举、固定字段列），与校验规则永不漂移。
- 前端批量导入页：顶部"下载模板"按钮；页内嵌"字段说明"表（每列含义、枚举值、目录约定、batch_no 与编号规则关系说明）。
- 批量导入与编号规则合并实现后，batch_no 列说明随规则启用状态动态展示。

## 四、后端流程

```
1. 前端把 zip 分片直传 MinIO（复用 init/complete 接口，object 前缀 batch-imports/）
2. POST /api/v1/batch-imports {object_key} → 创建 batch_import 记录（status=pending），异步执行导入
3. 导入任务：
   a. 下载/流式读取 zip → 解析 manifest.csv → 预检：
      - 每行字段完整性（完整字段强制）、枚举合法性、batch_no 查重（或触发自动编号）
      - 目录存在且非空；zip 中出现清单未声明的批次目录 → 报错
      - 预检失败 = 全有或全无：不创建任何批次，报告列出全部错误
   b. 预检通过 → 逐批次：创建 Batch（复用 BatchService，归属当前用户单位，
      batch_no 走编号规则或清单值）→ 递归解压目录内文件写入 MinIO
      → 建 DataFile 记录（batch_id/batch_no/device_no/modality 按扩展名推断）
   c. 汇总报告（成功 N 批次 M 文件 / 失败明细）写入 job.report
4. 前端轮询 GET /api/v1/batch-imports/{id} 展示进度与最终报告；完成后删除 zip 临时对象
```

## 五、数据模型与 API

### 5.1 新表 batch_import

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | str | 主键 |
| `status` | str | pending/running/succeeded/failed |
| `object_key` | str | zip 在 MinIO 的对象键 |
| `organization_id` | str \| None | 归属单位（普通用户=本单位；admin 默认本单位，可指定） |
| `creator_id` | str \| None | 创建人 |
| `total_batches` | int | 清单批次总数 |
| `done_batches` | int | 已导入批次数 |
| `report` | JSON | 结果报告（成功批次清单+失败明细） |
| `created_at` / `updated_at` | str | 时间戳 |

### 5.2 API

| 接口 | 说明 |
|------|------|
| `GET /api/v1/batch-imports/template` | 下载 manifest.csv 模板 |
| `POST /api/v1/batch-imports` | 创建导入任务（body: object_key）；普通用户可调，归属本单位 |
| `GET /api/v1/batch-imports/{id}` | 进度与报告 |
| `GET /api/v1/batch-imports` | 历史列表（admin 看全部，普通用户看本单位） |

### 5.3 其他

- 审计：每个批次创建记一条 audit（action="import"）。
- 幂等：zip 内同一目录名重复导入 → 报告提示跳过（batch_no 全局唯一兜底）。
- 异步实现：复用 FastAPI BackgroundTasks 或 asyncio 任务；SQLite 场景下导入任务串行执行（避免并发写锁）。

## 六、前端交互

- 批次列表页新增"批量导入"入口 → 批量导入页：
  1. 下载模板（按钮）
  2. 选择 zip 上传（分片直传，进度条，断点续传继承现有能力）
  3. 提交导入 → 轮询进度（完成批次/总批次）
  4. 结果报告页：成功批次清单 + 失败明细表（可复制）
- 与单批次上传互不影响。

## 七、与其他需求的衔接（合并实现顺序）

1. 两个新固定字段 + extras 扩展字段（manifest 列与校验依赖）
2. 批次编号自动生成规则（批量导入的 batch_no 自动生成依赖）
3. 多批次批量导入（依赖 1、2）

## 八、测试

- 单元（backend/tests/）：
  - manifest 解析：完整/缺字段/枚举非法/目录缺失/未声明目录 → 预检错误明细
  - 全有或全无语义：预检失败不创建任何批次
  - 附加列 → 批次 extras 落库；batch_no 自动生成衔接
  - 幂等重入：同目录重复导入跳过并报告
  - 模板下载：列头与示例行正确、UTF-8 BOM
- E2E（e2e/tests/）：构造小型 zip（2 批次 4 文件）→ 导入 → 批次列表出现 2 批次、文件归属正确、报告正确；错误包（缺字段）→ 全部拒绝且报告可读。
