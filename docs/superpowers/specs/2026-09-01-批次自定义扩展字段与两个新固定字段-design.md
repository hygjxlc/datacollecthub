# 批次自定义扩展字段与两个新固定字段 设计规格

> **状态：已确认，待实现**（用户 2026-09-01 指示"开始实现"）。

**目标：** 批次说明表（1）新增固定字段"数据对应设备:状态类型"（风电/火电/光伏下拉）与"涵盖模态数据"（按批次文件属性自动聚合，最多 8 种）；（2）允许用户自由扩充自定义键值对字段，下载时并入元数据 JSON 导出。

**技术栈：** FastAPI + SQLAlchemy + SQLite（后端）、Vue 3 + Element Plus（前端）

---

## 一、需求与现状

### 1.1 现状

- `Batch` 表 10 个固定字段：batch_no/device_no/device_model/station/license/sensitivity/owner_contact/is_synthetic/operating_condition/weather（[models/batch.py](file:///c:/Qoder/AIReady/datacollecthub/backend/app/models/batch.py)）。
- 铭牌台账已有 JSON 扩展先例：`Nameplate.extras: Mapped[dict | None] = mapped_column(JSON)`。
- 下载包已带元数据 JSON（`archive.py` `build_file_metadata` dump `BatchOut`，每文件文件夹内 `<文件名>.json` 含 batch 级全字段）。
- Excel 登记表（`storage/exporter.py`）：Sheet1"批次说明表"10 固定列。
- 列表页聚合已有先例：`file_count`/`total_size` 通过 `DataFile.batch_id` 分组聚合。

### 1.2 已确认决策（2026-09-01 用户选择）

| 决策点 | 结论 |
|--------|------|
| 扩展字段形态 | **自由键值对**（键名+值，存 extras JSON，与铭牌先例一致） |
| 导出位置 | **并入现有元数据 JSON**（batch 对象下 extras 子对象，不新增文件） |
| 字段 1 | `equipment_state_type`，必填，下拉枚举：风电/火电/光伏 |
| 字段 2 | `modalities`，只读聚合（批次下文件 modality 去重），最多 8 种，不落库 |
| extras 进 Excel | **默认不做**（用户未确认，YAGNI；两个固定字段进 Excel） |

## 二、详细设计

### 2.1 字段 1：数据对应设备:状态类型

| 项 | 设计 |
|----|------|
| 模型 | `Batch.equipment_state_type: Mapped[str | None] = mapped_column(String(16))`（可空=存量批次；新建必填由 schema 层校验） |
| 枚举 | 后端常量 `EQUIPMENT_STATE_TYPES = ("风电", "火电", "光伏")`；非法值 422 |
| Schema | `BatchCreate.equipment_state_type: str`（必填）；`BatchUpdate` 可选；`BatchOut` 输出 |
| 前端 | BatchForm 新增下拉（el-select 三选一）；列表页/详情页展示；存量空值显示"—" |
| 导出 | Excel Sheet1 新增一列"数据对应设备:状态类型"；元数据 JSON batch 对象新增该字段 |
| 批量导入 | manifest.csv 新增必填列（枚举校验） |
| 迁移 | `scripts/migrate_batch_state_type.py`：`ALTER TABLE batch ADD COLUMN equipment_state_type VARCHAR(16)`（幂等：列已存在则跳过） |

### 2.2 字段 2：涵盖模态数据（只读聚合）

| 项 | 设计 |
|----|------|
| 取值 | 批次下 `DataFile.modality` 去重集合，上限 8 种（SCADA/VIB/AUD/IR/CAM/VID/TXT/RPT） |
| 实现 | 不落库；列表页聚合查询追加 `GROUP_CONCAT(DISTINCT modality)`（SQLite 原生），与 file_count/total_size 同一查询；详情页/导出时单独聚合 |
| Schema | `BatchOut.modalities: list[str] = []`（聚合字段，同 file_count 性质） |
| 前端 | 列表/详情以中文标签展示（复用 MODALITY_LABELS：振动信号/红外热像等），只读，随文件增删自动变化 |
| 导出 | 元数据 JSON batch 对象输出 `modalities`；Excel 可选（默认不做） |
| 批量导入 | 无需清单列，导入完成后按文件自动聚合 |

### 2.3 扩展字段（extras 自由键值对）

| 项 | 设计 |
|----|------|
| 模型 | `Batch.extras: Mapped[dict | None] = mapped_column(JSON)`（与 Nameplate.extras 同款） |
| 校验 | 键不得与固定字段重名（10 字段 + equipment_state_type）→ 422；值仅 JSON 基本类型（str/int/float/bool/null）；键名 ≤64 字符；单批次 ≤20 个键 |
| Schema | `BatchCreate.extras: dict | None = None`；`BatchUpdate.extras` 可选（exclude_unset 更新）；`BatchOut.extras` 输出 |
| 前端 | BatchForm 底部"扩展字段"动态区：键值对行可增删；编辑回显 |
| 导出 JSON | `archive.py` `build_file_metadata` dump `BatchOut` 自然携带；结构：`batch: { ..., "extras": {"键": "值"} }` |
| 批量导入 | manifest.csv 支持任意附加列（表头列名=键名），导入时收集进各批次 extras |
| 迁移 | `scripts/migrate_batch_extras.py`：`ALTER TABLE batch ADD COLUMN extras JSON`（幂等） |

## 三、测试

- 单元（backend/tests/）：
  - 创建/更新批次带 equipment_state_type；非法枚举 422；必填缺失 422
  - modalities 聚合：多文件多模态去重正确、无文件为空列表
  - extras 创建/更新；键与固定字段冲突 422；嵌套对象/数组拒绝；超 20 键拒绝
  - 下载元数据 JSON 含 equipment_state_type/extras/modalities
- E2E（e2e/tests/）：表单下拉三选一创建批次 → 详情显示状态类型；上传不同模态文件 → 涵盖模态标签更新。
