# 批次编号自动生成规则 设计规格

> **状态：已确认，待实现**——与后续需求合并后一起编码（用户 2026-09-01 指示：先记下需求与方案，暂不编码）。

**目标：** 管理员在后台自定义批次编号规则，新增批次数据时批次编号由系统自动生成，不再手动输入。

**技术栈：** FastAPI + SQLAlchemy + SQLite（后端）、Vue 3 + Element Plus（前端）

---

## 一、需求与现状

### 1.1 现状

- `batch_no` 目前由用户在创建批次时**手动输入**（`frontend/src/components/batch/BatchForm.vue` 必填项，placeholder 提示"如 B2025-001"）。
- 后端 `BatchService.create_batch` 仅做应用层查重（同编号返回 422 "批次编号已存在"），无自动生成逻辑。
- `Batch` 表 `batch_no` 无数据库唯一约束；批次按单位隔离（`organization_id`）。
- 管理员后台现有页面：组织管理、用户管理；无系统规则配置模块。

### 1.2 需求（用户原话）

"如果管理员在后台自定义批次编号规则，后续增加新的批次数据，批次编号自动生成。"

### 1.3 已确认决策（2026-09-01 用户选择）

| 决策点 | 结论 |
|--------|------|
| 规则灵活度 | **模板表达式**：支持 `{PREFIX}` 风格占位符自由组合，可嵌入日期、设备编号等 |
| 作用范围 | **全局唯一规则**：全局 admin 统一配置一套规则，所有单位共用，编号全局唯一 |
| 手动关系 | **强制自动不可改**：启用规则后批次编号只读，完全由系统生成 |

## 二、方案对比（已选定方案 A）

| | 方案 A：规则表 + 原子计数器（**选定**） | 方案 B：规则表 + MAX(编号)+1 推导 | 方案 C：配置文件规则 |
|---|---|---|---|
| 并发安全 | 计数器原子自增，天然防撞号 | 两请求同时读 MAX 会撞号，需重试兜底 | 安全但需重启生效 |
| 序号连续性 | 删除批次不影响后续序号 | 删除中间批次后序号重用，可追溯性受损 | — |
| 后台动态配置 | 改规则即时生效 | 即时生效 | 改 .env 需重启容器，不满足"后台自定义" |
| 实现成本 | 新增 2 张表 | 新增 1 张表 | 最省但不满足需求 |

**选定理由：** 计数器表保证并发安全与序号连续；规则表支持后台即时修改；契合"强制自动不可改"对唯一性的硬要求。

## 三、详细设计

### 3.1 数据模型（新增 2 张表）

**batch_no_rule（规则表，全局单行）**

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | str | 主键 |
| `template` | str | 编号模板字符串，如 `B-{YYYY}-{SEQ:3}` |
| `updated_by` | str \| None | 最后修改人（用户 id） |
| `updated_at` | str | 最后修改时间 |

**batch_no_counter（计数器表）**

| 字段 | 类型 | 说明 |
|------|------|------|
| `counter_key` | str | 主键；模板固定部分 + 日期维度拼接，如 `B-2025-`（模板含 {YYYY} 时按年隔离，序号每年从 1 起） |
| `value` | int | 当前序号；事务内 `UPDATE ... SET value=value+1 RETURNING value` 原子自增 |

### 3.2 模板占位符语法（YAGNI 最小集）

| 占位符 | 含义 | 示例 |
|--------|------|------|
| `{YYYY}` `{YY}` `{MM}` `{DD}` | 创建日期 | `B-{YYYY}-{SEQ:3}` → `B-2025-007` |
| `{SEQ:n}` | 序号，n 为位数补零 | `{SEQ:4}` → `0007` |
| `{DEVICE_NO}` | 批次所属设备编号 | `F01-{YYYY}-{SEQ:3}` → `F01-2025-007` |

- 其余字符为固定文本；模板**必须含 `{SEQ:n}`**，保存时校验未知占位符并拒绝（422）。
- **序号重置规则**（自动推导）：模板含 `{YYYY}` → 按年重置；含 `{MM}` → 按月重置；都不含 → 永不重置。

### 3.3 编号生成流程（`BatchService.create_batch` 内）

```
1. 读规则：无规则 → 回退现状（手动输入 batch_no，兼容存量环境）
2. 解析模板 → 组装 counter_key（固定部分 + 当前日期）
3. 计数器原子自增取序号 → 拼接完整编号
4. 以 batch_no 全局唯一索引兜底：撞号则重试 3 次
```

- **存量兼容**：首次启用规则时，扫描存量批次中匹配当前模板的最大序号作为计数器起始值，避免撞存量编号。
- **规则修改后**：counter_key 变化（如换前缀）→ 序号从 1 重新开始，同样扫存量兜底。
- **最终防线**：`Batch.batch_no` 增加数据库唯一约束（现仅应用层查重）。

### 3.4 API 与前端

| 层 | 变更 |
|----|------|
| 后端 API | `GET /api/v1/admin/batch-no-rule`（读取，admin 权限）；`PUT /api/v1/admin/batch-no-rule`（保存并校验模板，admin 权限）；`BatchCreate.batch_no` 改为可选——有规则时忽略前端值强制生成 |
| 管理员后台 | 新增"批次编号规则"页（与组织管理、用户管理并列）：模板输入框 + 占位符说明 + 实时预览（如 `B-2026-001`）+ 保存 |
| 批次表单 | `batch_no` 输入框改为**只读**，创建时由后端生成回显（规则未配置时保持现状手动输入） |

### 3.5 错误处理与测试

- 模板非法（缺 {SEQ}、未知占位符）→ 保存时 422 拒绝。
- 计数器重试 3 次仍冲突 → 返回 409。
- 单元测试（`backend/tests/`）：占位符解析、按年/按月/永不重置、存量最大序号兜底、并发自增模拟、模板校验、规则未配置时回退手动。
- E2E（`e2e/tests/`）：admin 配置规则 → 普通用户创建批次 → 编号自动生成且只读。

## 四、范围边界（YAGNI）

- 不做可视化规则构建器；不做单位级独立规则（已确认全局唯一）。
- 不支持 `{ORG}` 单位代码占位符（Organization 表无 code 字段，全局规则下无必要）。
- 不回溯修改存量批次编号——规则仅对新建批次生效。
